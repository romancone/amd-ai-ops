2. Context and memory

2.1 Full-context limits

No 4 × 256K result is established. The 1/2/4-user speed and image tests allocated 16,384 tokens per user: 16,384 / 32,768 / 65,536 total. Their requests did not fill those allocations. Full-cache thresholds for 2 or 4 users, or with MTP on, remain unknown.

The six full-context checks used one user, MTP off and f16/f16 cache. A pass processed context minus 128 input tokens and generated 128 tokens without dropping input or shifting context.

With MTP off, allocated and usable context are equal. Practical settings left at least 512 MiB GPU memory spare during full-fill and image checks; Qwen/HIP left 525.65 MiB at 244K. E4B and Gemma 12B reached their model limits, not a proven hardware failure threshold. Qwen/Vulkan lost the device at 252K and 256K; its 16K short-request tests passed. Do not multiply the one-user limits by the number of users.

For MTP, four guard tokens would reduce a 16,384-token allocation to 16,380 usable tokens per user. That is the intended input/output budget, not a validated full-fill capacity. Q8/Q8 and Q4/Q4 full-context thresholds are not established by these six checks.

A capacity pass means the model read a full prompt of repeated text and generated 128 tokens without dropping input. This checks memory and execution, not understanding of long conversations. Images were checked before filling the context.

  • E4B Q8 at 128K: Vulkan/Q4 uses less memory and generates faster; HIP/Q4 reads the prompt faster. Both still make image-description mistakes.
  • Qwen Q8 at 256K: use Vulkan/Q4 for faster prompt reading and answers.
  • Gemma 12B Q8 at 256K: use HIP/Q4. Vulkan/Q4 answered image questions but failed near 229K tokens.

Other failures: Gemma 12B/HIP with Q8 cache ran out of memory on images. Vulkan with Q8 cache failed near 155K tokens for Qwen and 115K for Gemma 12B. Qwen/HIP with Q8 cache passed with only about 12 MiB free; use Q4 cache for more space.
