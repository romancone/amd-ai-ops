Image quality, cache and memory

RX 6900 XT 16 GiB · one user · Flash Attention (FA) on · BF16 image projectors · thinking and MTP off. Tests cover HIP and Vulkan with f16, Q8 and Q4 caches.

54 configurations at 16K; 18 at maximum context: 10 passed, 4 failed, 4 excluded. Context is how much text the model can hold. All 52 successful image answers at maximum context matched the 16K answers.

Q8 vs Q4: image quality

Q8 offers no consistent image-quality advantage in these tests. For Qwen, use Q4_K_M with Vulkan, f16/f16 cache and Flash Attention on.

8 GiB budget

Use Qwen Q4_K_M / Vulkan / f16 for images at 16K. Q4 cache saves memory: 6.63 GiB with a 97.75% image score. These choices still need testing on an 8 GiB card.

16 GiB budget

Use Gemma 12B Q4 / HIP / f16 for text and images at 16K. Q8 uses more memory and generates answers more slowly.

Above 16 GiB

Not run. Qwen Q8 and Gemma 12B Q8 with f16 cache at 256K are estimated to exceed 16 GiB on both backends.

A capacity pass means the model read a full prompt of repeated text and generated 128 tokens without dropping input. This checks memory and execution, not understanding of long conversations. Images were checked before filling the context.

  • E4B Q8 at 128K: Vulkan/Q4 uses less memory and generates faster; HIP/Q4 reads the prompt faster. Both still make image-description mistakes.
  • Qwen Q8 at 256K: use Vulkan/Q4 for faster prompt reading and answers.
  • Gemma 12B Q8 at 256K: use HIP/Q4. Vulkan/Q4 answered image questions but failed near 229K tokens.

Other failures: Gemma 12B/HIP with Q8 cache ran out of memory on images. Vulkan with Q8 cache failed near 155K tokens for Qwen and 115K for Gemma 12B. Qwen/HIP with Q8 cache passed with only about 12 MiB free; use Q4 cache for more space.
